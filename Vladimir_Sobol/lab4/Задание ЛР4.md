# Лабораторная работа №4

Лабораторная работа 4\. Промпт как программа

Курс: Автоматическая обработка текстов

**Цель**

Спроектировать LLM-компонент как проверяемый программный интерфейс: с формальной схемой результата, тестами, валидацией и контролем неподтверждённых извлечений.

**Исходные данные**

Используйте 50 русскоязычных отзывов из RuDReC или аналога

**Задача**

Для каждого текста извлеките препарат, показание или симптом, положительный эффект, нежелательную реакцию и фрагменты текста, подтверждающие извлечение.

**Выходная схема**

{  
  "drug": \[\],  
  "indication": \[\],  
  "positive\_effect": \[\],  
  "adverse\_reaction": \[\],  
  "evidence": \[\]  
}

**Задание (индивидуально)**

1. Создайте простой промпт без примеров и сохраните его как version\_1.  
2. Создайте version\_2: добавьте точное описание полей, правила обработки отрицаний и два размеченных примера.  
3. Опишите выход через Pydantic и реализуйте проверку структуры.  
4. Добавьте проверку: каждый элемент evidence должен дословно встречаться в исходном тексте.  
5. При невалидном ответе разрешается ровно один повторный запрос с описанием ошибки. Реализуйте и зафиксируйте этот механизм.  
6. Создайте десять автоматических тестов по перечню ниже.  
7. Сравните version\_1 и итоговую систему по валидности JSON, качеству извлечения и числу неподтверждённых результатов.

**Обязательные тестовые случаи**

1. пустой текст;  
2. препарат не указан;  
3. несколько препаратов;  
4. эффект отрицается;  
5. эффект предполагается;  
6. реакция относится к другому человеку;  
7. текст содержит цитату;  
8. название написано с ошибкой;  
9. LLM возвращает лишнее поле;  
10. LLM указывает evidence, которого нет в тексте.

**Что сдаётся**

1. version\_1 и version\_2 промпта;  
2. Pydantic-схема;  
3. не менее десяти pytest-тестов;  
4. CSV или JSONL с результатами;  
5. отчет, куда включен анализ пяти ошибок.
